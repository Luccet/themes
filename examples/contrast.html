The measure is *contrast ratio*, from the [Web Content Accessibility Guidelines](https://www.w3.org/TR/WCAG22/) (WCAG 2), and it is a number anyone can compute. ## What the number is A colour's *relative luminance* $L$ is the light it gives off, as the eye weighs it, from $0$ for black to $1$ for white. Each channel of an sRGB colour, read as a fraction $c$ of 255, is first made linear,[^threshold] $$ c_{\text{lin}} = \begin{cases} c / 12.92 & \text{if } c \le 0.04045, \\ \left( \dfrac{c + 0.055}{1.055} \right)^{2.4} & \text{otherwise,} \end{cases} $$ {#eq-linear} then the three are weighted, green the most, since the eye is most sensitive to it: $$ L = 0.2126\, R_{\text{lin}} + 0.7152\, G_{\text{lin}} + 0.0722\, B_{\text{lin}}. $$ {#eq-luminance} Two luminances give the ratio, the lighter $L_1$ over the darker $L_2$: $$ \frac{L_1 + 0.05}{L_2 + 0.05} $$ {#eq-ratio} It runs from $1$, a colour on itself, to $21$, black on white. The $0.05$ stands for the light a screen reflects: without it, any ratio with black, at $L = 0$, would be infinite. [^threshold]: WCAG 2.0 gave the threshold as 0.03928, from a draft of the sRGB standard; the text has given sRGB's 0.04045 since 2021, noting that the change has no practical effect. No 8-bit channel falls between the two (10/255 is 0.0392, 11/255 is 0.0431), so for a colour written in hex they agree. `build.js` still uses 0.03928. ## How much is enough > The visual presentation of text and images of text has a contrast ratio of at least 4.5:1, > except for the following: … > > — [WCAG 2.2, success criterion 1.4.3](https://www.w3.org/TR/WCAG22/#contrast-minimum) :::table[The least contrast WCAG 2 asks for]{#tbl-levels} | Level | Body text | Large text | Controls and graphics | |---|---|---|---| | AA | 4.5:1 | 3:1 | 3:1 | | AAA | 7:1 | 4.5:1 | | ::: *Large text* is 18 points, or 14 points bold: about 24 and 18.7 CSS pixels. The themes here hold every text colour to ==4.5:1==, and High contrast to 7:1; the border of a control, such as a key like :kbd[Esc], to 3:1. On white, the lightest grey for body text is `#767676`, at 4.54:1; one step lighter, ~~`#777777`~~ falls short at 4.48:1. @fig-greys shows the lightest grey for each ratio. ![The lightest greys that reach 3:1, 4.5:1 and 7:1 on white.](img/greys.svg){#fig-greys width=600 alt="Three samples of grey text on white: #949494 at 3.03:1 for large text, #767676 at 4.54:1 and #595959 at 7.00:1 for body text"} ## Palettes as their authors made them Editor palettes are made for code, and many keep comments faint on purpose. @tbl-comments measures some against their own page and code backgrounds. :::table[Comment colours, as their palettes give them]{#tbl-comments} | Palette | Comment | On the page | On code | |---|---|---|---| | Dracula | `#6272a4` | 3.03:1 | 2.51:1 | | Gruvbox, dark | `#928374` | 4.02:1 | 3.16:1 | | Nord | `#616e88` | 2.43:1 | 1.96:1 | | One Light | `#a0a1a7` | 2.47:1 | 2.26:1 | | Solarized, light | `#93a1a1` | 2.48:1 | 2.18:1 | ::: None reaches 4.5:1 on code. `build.js` raises such a colour: it mixes it toward white on a dark page, toward black on a light one, a fiftieth at a time, until it reaches its ratio, and the theme's header names each colour it raised. ## The computation @lst-contrast is @eq-linear to @eq-ratio as `build.js` computes them; line 5 is @eq-linear, with WCAG 2.0's threshold. ```js[Contrast ratio, from build.js]{#lst-contrast lines hl=5} // WCAG 2's relative luminance of a colour written #rrggbb. function luminance(hex) { const [r, g, b] = [1, 3, 5].map((i) => { const c = parseInt(hex.slice(i, i + 2), 16) / 255; return c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4; }); return 0.2126 * r + 0.7152 * g + 0.0722 * b; } // The ratio of two colours, from 1 to 21. function contrast(a, b) { const [x, y] = [luminance(a), luminance(b)]; return (Math.max(x, y) + 0.05) / (Math.min(x, y) + 0.05); } ``` `contrast('#767676', '#ffffff')` returns 4.542… ## In the browser Browsers measure it too. In Chrome's developer tools: 1. Pick a piece of text with :kbd[Ctrl]+:kbd[Shift]+:kbd[C] (:kbd[Cmd]+:kbd[Shift]+:kbd[C] on a Mac). 2. In *Styles*, click the swatch of its `color`: the picker gives its contrast ratio against the background, with the AA and AAA lines drawn across the colours. 3. To see the dark palette, open the command menu with :kbd[Ctrl]+:kbd[Shift]+:kbd[P] and run **Emulate CSS prefers-color-scheme: dark**. *Rendering* emulates `prefers-contrast: more` as well. Firefox's *Accessibility* panel checks every text on the page at once. ## Before a palette ships - [x] Every text colour reaches 4.5:1 on the page and on code - [x] Code colours reach 3:1 on a highlighted line - [x] A control's border reaches 3:1 against the page - [ ] Read by eye, in light and in dark - [ ] with `prefers-contrast: more` - [ ] printed, which `luccet.css` turns dark on white
